# Decision log

The decisions that bind this source, with the reason for each and what follows from it. `Adopted` means the source
implements the decision. `Deferred` means the source and its tests exist but nothing is deployed or enabled by Phase 1.
The code and Terraform are authoritative; see [README.md](README.md) for how the documents relate.

| ID | Status | Decision | Rationale and consequence |
|---|---|---|---|
| D01 | Adopted | Use the Microsoft-managed Azure SRE Agent (`Microsoft.App/agents`), optional behind `deploy_managed_agent` (default false). | No custom agent platform to build or secure. The agent runs in Review mode with access level Low, holds read roles only and has no Contributor role. |
| D02 | Adopted | Cover five use cases: Linux disk RCA, alert noise and overlap, proactive capacity trend, patch (Azure Update Manager) investigation and backup (Azure Backup) triage. | Replay fixtures are not proof for the patch and backup cases. The intended evidence is a real Update Manager or Azure Backup failure produced by a bounded fault driver. |
| D03 | Adopted | Use three separate Linux VMs (`linux`, `patch`, `backup`) and a control service in Container Apps jobs outside the guests. | A fault on one VM cannot disable another VM's recovery or evidence collection, and the controller never runs inside a faulted guest. |
| D04 | Adopted | Use an isolated VNet (`10.42.0.0/16`) with explicit NAT egress and no hub membership. | Joining a shared network would change the blast radius of every fault. Any shared-network change needs a separate decision. See [runtime-networking.md](runtime-networking.md). |
| D05 | Adopted | Keep the agent Review-only. Any autonomous repair belongs to a separate sandbox workflow. | The agent identity cannot execute a repair. Review mode or an Ask policy is not an execution authorization boundary; bounded execution would belong to an authenticated runner, which is not part of Phase 1. |
| D06 | Adopted | Inspect and recover faults that stop an Azure guest component (the backup guest agent) through independent SSH and a guest-local watchdog, not Run Command. | Azure VM Run Command depends on the component that the fault stops, so it cannot be the inspection or recovery path. |
| D07 | Adopted | Induce the real Azure Backup failure with a bounded Azure Policy deny (`scripts/Invoke-BackupPolicyProbe.ps1`). | A temporary built-in "Not allowed resource types" assignment on the backup restore-point resource group makes one native backup fail at the snapshot step, without touching the guest. The claim is the failure only, not repair or a replacement backup. |
| D08 | Adopted | Use one typed Terraform root separated by concern. No reusable modules, no azd or Bicep lifecycle. | Avoids speculative abstraction before reuse exists. Providers and the Terraform version are pinned. |
| D09 | Adopted | Use separate deployment and runner SSH keys and accounts (`admin_ssh_public_key`, `runner_ssh_public_key`). | The Azure administrative account is not a constrained repair identity. The runner account `asrerunner` has a forced-command key and a sudoers entry limited to the guest helper in `--inspect-only` mode. The two keys must differ. |
| D10 | Adopted | Limit knowledge to four reviewed documents and give each handler its own tools and instructions. | The repository is never attached as unfiltered knowledge. Controller code, test fixtures and fault configuration are excluded. See [native-review-workflows.md](native-review-workflows.md). |
| D11 | Adopted | Keep faults disabled by default and make every fault expire independently of the controller. | Each driver is time-bounded (the incident drivers at most 900 seconds; the backup policy probe has its own limits), needs the original scenario id to reset, installs independent expiry before mutating and never retries or renews. See [implementation.md](implementation.md). |
| D12 | Adopted | Run Terraform from the operator's workstation through `scripts/Invoke-Terraform.ps1`, not a pipeline. | The wrapper requires Terraform 1.11.2, writes a saved plan with a hash-pinned manifest that expires after four hours, and applies only from a reviewed saved plan. It refuses any delete or replace, refuses a dirty tree unless `-AllowDirty`, and removes ambient service-principal, OIDC and MSI variables. |
| D13 | Adopted | Keep remote state in an Entra-only storage account created by `scripts/Initialize-TerraformState.ps1`. | Shared-key access is off and the firewall allows only the operator address. The backend is partial and `infra/environments/backend.hcl` is git-ignored. Local state is never used to work around remote state. Every run reads the account back after its writes and fails closed, before any backend file is written, if public network access is not `Enabled`. A tenant Modify policy that forces it off (for example `StorageAccount_PublicNetwork_Modify`) is handled by the opt-in switch `-ApplyPolicyExclusionTag`: it tags only the state account `SecurityControl=Ignore` (create call or merge) and the read-back also requires the tag. It is off by default, never automatic, and the tag is a self-service bypass controlled only by RBAC and the Activity Log, so the policy owner signs off. Rejected: a Network Security Perimeter (would need `SecuredByPerimeter` and a perimeter this design does not own), local Terraform state, tagging the resource group (the policy honours it for every account in the group), applying the tag automatically or retrying with it, and automating a policy exemption (the governed alternative stays manual). |
| D14 | Adopted | Derive all configuration from one context document (`asre-context/v1`) that Terraform emits. | One source for names and ids; loaders fail closed; ids are derived from `subscription_id` plus conventions and never stored. Tests run on synthetic contexts, and a leak detector proves no deployment value is hard-coded. |
| D15 | Adopted | Render agent assets per deployment from committed synthetic assets (`scripts/Render-AgentAssets.ps1`). | Publication scripts take only a rendered, verified tree. A verify mode re-renders in memory and requires byte equality, so a sentinel value cannot reach the agent. |
| D16 | Adopted | Deploy the observe-only handler `asre-azure-monitor-observe` first. | An Azure Monitor alert opens an automatic Review-mode thread with one read-only evidence tool, no case tool, no hook and no skills. The incident filter is published disabled and enabled last, after a typed agent-name confirmation. |
| D17 | Adopted | Confine writes of the agent plane (`scripts/AgentPlane.Common.ps1`). | https on port 443 only, no redirects, ARM host fixed to the context subscription. ARM writes are allowed only on children of the agent resource and as PATCH on the agent resource; Terraform owns its lifecycle. A read-only plane blocks every non-GET. |
| D18 | Adopted | Create all seven alert rules disabled; `enabled_native_alert_rules` enables selected ones. | Alerting starts only on purpose. The variable can enable `disk`, `patch-installation`, `noise-overlap`, `capacity-growth` and `backup-job`; `workload-oom` and `heartbeat` stay disabled. |
| D19 | Adopted | Enable backup protection with one flip: `backup_protection_enabled` is false on the first apply and true on the second. Never use `-target`. | Protection cannot be silently destroyed: the protected item, the vault and the Key Vault have `prevent_destroy`, so the flip is one-way. The variable defaults to false, so a plan that does not ask for the flip never creates the protected item; `demo.tfvars.example` also sets it explicitly. |
| D20 | Adopted | Limitation: custom role names are unique per tenant. | A second deployment of this module into another subscription of the same tenant collides on the custom role names (one is created in this release; the module defines six in total). |
| D21 | Deferred | ServiceNow case management: the production Review handler `azure-monitor-review`, its case tool and its hooks. | Source and tests exist and the assets are declared inert in `scripts/AgentAssets.map.json`; nothing is published or enabled. Enabling it needs the optional `servicenow` context part and the agent endpoint. |
| D22 | Deferred | The operator dashboard. | Source and tests exist in `dashboard/`; the `dashboard` Terraform variable stays disabled. When enabled it needs a viewer group and an operator object id. |
| D23 | Deferred | A CI/CD pipeline. | Phase 1 is workstation-only. A pipeline would have to keep the same saved-plan rules: no replanning at apply, no deletes, and a protected path to the state account. |

When a decision changes, keep its ID and record what superseded it and why, in the same row.
