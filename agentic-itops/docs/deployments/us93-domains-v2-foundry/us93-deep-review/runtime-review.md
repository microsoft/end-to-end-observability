## Positive evidence

- All six OpenAPI outputs structurally match their generator functions (probe, no regenerated repo files).
- Existing offline suite: 67 pytest cases pass. Evaluation suite: 41/41 pass. Nine-agent legacy dry-run completes and displays all definitions without touching Azure.
- Core adapter, gate and BM25 paths really execute offline. Current harness always returns `executed=false`.
- MCP documentation explicitly identifies its stub limitations. There is no reason to label the absence of a remote listener a concealed implementation; it is a planned service gap.
- Generated files, local examples and demonstration policy are useful starting points, not production acceptance.

`contract-probe-results.json` records 13 reproduced behavioral gaps/default hazards and one six-spec parity check. These are focused offline observations, not 13 independently severity-scored vulnerabilities or live-model tests.

Additional `live-boundary-probe-results.json` uses fake SDK/client objects only: partial Logs response raises AttributeError on `.tables`; live Search sends only lexical query arguments using key credentials and discards returned documented_actions; a fake vector store with zero indexed/eleven failed files is still returned as usable. These reproduce local branch behavior, not real service compatibility or authorization. No data was uploaded to a service.

## Configuration/host recommendation to integrate into recreated plan

Keep all nine prompt agents. Use actual Foundry orchestration/delegation via a proven current API binding, not the local three-call harness. Expose deterministic tools on the documented authenticated Function-style host; a different host is an explicit infrastructure choice. Add a lifecycle driver separately (input, triage/context, closure, hygiene), Search with declared semantics and real remote MCP. Do not treat every agent as an always-running container or every agent invocation as the same workflow.

Preserve the user-approved producer and old add-on. The new runtime needs its own observation-reader identity and separate knowledge/tool permissions. Host/model/Search choices require preflight and approvals; source review is not cloud authorization.
